# Complete Practical Workflow

This workflow is derived directly from the uploaded task.

## Phase 1 — Create the Required User

### Step 1. Create `agent007`

**Account:** authorized administrator using `sudo`

Run:

```bash
sudo useradd -m -s /bin/bash -G sudo agent007
```

**Purpose:** Creates `agent007`, creates the home directory, assigns `/bin/bash`, and adds the user to the `sudo` group.

**Verification:**

```bash
id agent007
getent passwd agent007
```

**Expected result:** `agent007` exists, is associated with a home directory, uses `/bin/bash`, and is a member of the `sudo` group.

**Evidence:** Capture the successful user verification if your instructor requires evidence of this step.

## Phase 2 — Set Password and Switch User

### Step 2. Set the password

**Account:** authorized administrator

Run:

```bash
sudo passwd agent007
```

Enter the password when prompted.

**Expected result:** The password is set for `agent007`.

**Note:** Do not place the actual password in this repository.

### Step 3. Switch to `agent007`

**Account:** administrator before switching

Run:

```bash
su - agent007
```

Then verify:

```bash
whoami
pwd
```

**Expected result:**

- `whoami` reports `agent007`.
- `pwd` should place you in the new user's home directory.

**Evidence:** Capture a screenshot showing `whoami` and the current working directory if useful.

> From this point, file operations should be performed as `agent007`, except for the explicitly required root ownership operation in Phase 7.

## Phase 6 — Set and Verify Permissions

### Step 9. Set `targets.txt` permissions

**Account:** `agent007`

The required permissions are:

- Owner: read + write
- Group: read only
- Others: no permissions

This corresponds to numeric mode `640`.

Run:

```bash
chmod 640 targets.txt
```

**Verification:**

```bash
ls -l targets.txt
```

**Expected permission representation:**

```text
-rw-r-----
```

The ownership and timestamps are intentionally not fabricated here; record your actual result.

**Evidence:** Capture `chmod 640 targets.txt` followed by `ls -l targets.txt`.

## Phase 8 — Explicit Root Ownership Operation

### Step 12. Change ownership as root

This is the one explicit task step that requires root.

**Important:** Do not perform ordinary file operations as root. The uploaded task specifically says:

> As root, change the ownership of `intel/targets.txt` to another user (e.g., `root`), then switch back to `agent007` and observe the result using `ls -l`.

Switch to root using an authorized method, for example:

```bash
sudo -i
```

Then run the ownership change using the user selected for the task. The task gives `root` as an example:

```bash
chown root /home/agent007/mission/intel/targets.txt
```

Then leave the root shell:

```bash
exit
```

**Account after `exit`:** return to `agent007`.

Verify:

```bash
whoami
ls -l /home/agent007/mission/intel/targets.txt
```

**Expected result:** `whoami` reports `agent007`, while `ls -l` shows the actual owner selected in the root ownership command.

**Evidence:** Capture the ownership change and subsequent `ls -l` observation if required.
